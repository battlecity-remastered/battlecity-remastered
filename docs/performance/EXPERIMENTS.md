# Experiment and decision record — 2026-10-03

This is the durable handoff for future LLMs. Read [REPORT.md](REPORT.md) before interpreting these trials. [experiment-inventory.json](experiment-inventory.json) lists every raw measurement/capture directory, configuration, metric and artifact. Nothing in this table authorizes sacrificing visual fidelity. Revisit rejected ideas when hardware or profiling evidence changes, rather than assuming a rejection is universal.

Each label below refers to `evidence/<label>-demo/` unless another mode is given. Results are hardware-specific. FPS is wall-clock RAF throughput, not 60 Hz simulation speed. Every performance trial contains real movement/camera movement/combat and animated scenery; captures are separate fixed-state visual tests.

## Measurement corrections that must survive this conversation

1. **Cold browser/driver confounded the early sequence.** Original demo initially measured 15.22 FPS, then original source restored later measured 27.34 and 27.31 FPS. Early 15→19→22→27 progression cannot be attributed to the successive optimisations. Final improvement uses the repeated warmed original runs, not the cold result. Draw-call/triangle changes are deterministic and still useful in those early trials.
2. **Original live join already prepared city models.** The first live run omitted this preparation (15.70 FPS, 198 compile/link calls). Warm repeat live runs use `prepare=1`, matching the real joined-world path: 26.25/25.89 FPS, 69 compile/link calls in the first gameplay frame. Final comparisons use these prepared originals.
3. **The initial orthographic AO experiment had a shader error.** A conditional referenced `PERSPECTIVE_CAMERA`, which the native denoiser does not define. The 29.77 FPS result is invalid and must not count as a gain: the denoiser shader failed. The corrected guarded orthographic implementation ran with zero errors at 28.55 FPS. The harness now exits unsuccessfully if any browser error is recorded.
4. **Early GC reports counted nested trace spans.** Use native top-level `MinorGC`/`MajorGC`, not every event whose name contains GC. Early directories have corrected `gc-pauses.json` where applicable; later result files use the corrected controller. Do not sum nested V8 phases as independent pauses.
5. **Shader events in originals occur during initial gameplay warm-up.** The 189 demo and 69 prepared-live compile/link calls occur before the measured 720-frame steady window. Both original and final have zero compile/link calls after the 120-frame warm-up on this route. Final prewarming additionally removes those first-gameplay-frame compilations; it is not evidence that the original compiled shaders on every steady frame.
6. **The initial live combat fixture only emitted muzzle effects.** Calling demo `cannon.launch` while live network frames own shell presentation does not produce active network projectiles. Earlier `baseline-repeat-*-live`, `direct-resolve-live`, `final-2/3-live` and `final-check-live` therefore represent moving enemies plus muzzle effects. These results are retained, but the final live comparison uses `baseline-combat-2/3-live` and `final-combat-2/3-live`: production fired/resolved events, shared bullet motion, three weapon types, impacts and 3–5 active shells. Corrected pooled live performance is 26.03→26.99 FPS (+3.70%), calls 845.22→679.15, p95 46.1→45.5 ms, p99 57.8→55.3 ms. Original first-gameplay compile/link calls are 72, final zero.

## Diagnostics and rejected changes

| Attempt / artifact | Measurement or reasoning | Disposition |
|---|---|---|
| `gpu-color`, `pass-color` | First timer attempt (`gpu-color`) still measured total frame GPU time, 31.86 ms. Correct selective scene timer (`pass-color`) measured 21.64 ms, including shadow rendering. | Diagnostic only. Use the explicit pass selection/configuration, not the label, to determine timer scope. |
| `probe-ao` | Native AO pass 7.52 ms GPU, including normal/depth geometry, AO sampling, denoising and colour blending. | Identifies a large separate GPU component. Preserving AO is a visual constraint. |
| `pass-bloom` | Bloom 1.43 ms GPU; default threshold/strength/radius/mip sizes unchanged. | Diagnostic. Paired Gaussian taps were investigated mathematically but not implemented: limited budget share, and higher horizontal mips sample a larger source than their destination so naive adjacent-tap pairing changes the filter. |
| `probe-fill` | Diagnostic DPR .5: 57.61 FPS / 13.13 ms GPU vs full resolution ~27.6 / 31.05. Four times fewer framebuffer pixels, nearly doubled throughput. | Confirms fill-rate/shading limitation. Reject as a production optimisation because it visibly lowers resolution. Production DPR cap, framebuffer and antialiasing remain unchanged. |
| `probe-shadow` | Diagnostic shadows off: 30.31 FPS / 27.56 ms GPU. One shadow-casting sun, 2048² PCF; no point-light shadow casters. | Diagnostic only. Do not disable shadows or lower their size/filter quality. Static cache considered but not implemented: the sun's volume follows the camera and tanks/turrets/rotors move; blindly skipping updates changes shadows. |
| `probe-no-ao` | Diagnostic native colour copy replacing AO: 34.10 FPS / 24.23 ms GPU on the final architecture. | Confirms remaining AO cost; never used in production. Copy pass retains composer buffer swapping so this diagnostic does not break MSAA order. |
| `shader-math` and its normal image/diff | Unrolled all five terrain FBM octaves and replaced cellular two-nearest-distance branching with squared distances/min/max and final square roots. 27.46 FPS vs ~27.24 before; no convincing gain. Visual mean error .101/255. | Reverted terrain shader to original. Compiler apparently already handles this work effectively on this GPU. No shader quality simplification retained. |
| `probe-order` | Global opaque front-to-back ordering instead of material-first ordering: 27.44 FPS vs direct-resolve 27.62; CPU 16.77 vs 15.41 ms. | Reject: worse CPU/material switching without useful overdraw benefit. Exists only as a benchmark diagnostic. |
| `fused-ao` | Prototype subclass ran native AO with output Off, then one colour×AO shader instead of native copy+blend. 27.29 FPS / 31.22 ms GPU vs 27.62 / 31.05. One fewer draw, no reliable benefit; one 23 ms GC pause made tails worse. | Removed the subclass entirely. No justification for extra compositing code or rounding risks. A prototype typecheck also found optional render arguments mismatching the base signature; it was never retained. |
| `orthographic-ao` | 29.77 FPS, one denoiser fragment compilation error caused by undefined preprocessor symbol. | Invalid experiment, corrected and rerun as `orthographic-fixed`. Do not cite this apparent gain. Error text and trace are retained. |
| `instanced-only` | Disable mixed-geometry batching: 29.05 FPS / 12.66 ms CPU / 29.40 ms GPU; 871.00 calls and 1,146,448 triangles. Lower memory/program count (86). | Not selected as the overall final architecture: a single run was slightly faster but restored essentially all original calls. Its cheaper per-vertex work motivated static merging, which retains draw reduction with lower CPU/memory than all-multi-draw. This alternative remains worth retesting on other hardware; do not claim hybrid is universally faster. |
| `shared-shadow` | Prototype rotated five constant Vogel-disk offsets with a shared sin/cos pair, retaining five native PCF samples; also tried equivalent cubic normal weights in denoising. 28.87 FPS / 29.61 ms GPU vs static merge 28.84 / 29.73. | Both reverted: ~.1 ms GPU is within noise, insufficient to retain more shader patching. No shadow sample count, position distribution or filter quality change applied. |
| LOD, lower MSAA/shadow/AO/bloom quality, global/adaptive resolution reduction | Profiling confirms full-resolution shader work dominates. Visible rocks/building silhouettes and animated lava are the visual identity. | Not implemented. No demonstrated imperceptible transition or image-preserving resolution strategy justified a compromise. |
| Lower AI/physics frequency, remove effects, merge transparent meshes indiscriminately | Movement costs around .4–.5 ms; gameplay changes are disproportionate to this measured cost. Transparent sorting and effect silhouettes matter. | Not implemented. Gameplay/animation rates and collision remain unchanged. |

## Visual and verification history

Original captures: `baseline-demo-{close,normal,wide,lava}` and `baseline-live-normal`. `baseline-detail-demo-normal` additionally inspects the original model geometry; it is not a timed optimisation trial. Intermediate comparisons are in `lava-chunks-visual`, `material-batches-visual`, `material-pool-fixed-visual`, `terrain-groups-visual`, `shader-math-visual`, and `static-merge-visual`. Keep the failed material comparison: it demonstrates a real regression caught by the guard.

Final captures: `final-demo-{close,normal,wide,lava}` and `final-live-normal`, with matching `-comparison` folders. The corrected live original is `baseline-combat-live-normal`; its final comparison supersedes the initial flash-only live comparison. Canonical final screenshot labels were refreshed during confirmation; independent timed experiment labels remain preserved. They preserve tank/building silhouettes, material wear, close scenery, rock/lava geometry, shadows, transparent steam/arcs/particles, bloom and heat distortion. Reviewed amplified differences contain small noise/particle/rounding changes, not missing structures or softened imagery. Mean channel errors range .014–.156/255; large channel differences occur in at most .0047% of pixels. Passing the threshold is not a claim of pixel-identical output.

`evidence/checks-before-refactor/` retains the first full validation: 551 tests passed, all checks except strict complexity passed. Complexity 17 in the batching update exceeded 15. Extracted transform upload/bounds refresh helpers; `evidence/checks/` then passed every required check. Earlier individual development logs, including failed checks and the initial restricted-environment socket-test run, remain at the evidence root. Some old logs reflect intermediate files; the canonical final status is `checks/results.json`.

`evidence/checks-live-replay-before-fix/` additionally preserves two fixture-check failures: the general protocol envelope builder loses payload type information, and an impact-count assertion failed to allow production culling of distant laser impacts. Final replay uses the typed `makeKnownEnvelope` builder; its runtime event content is equivalent. The focused test verifies continuously active, moving projectiles of all three weapon types plus nearby impacts while respecting distant-effect culling.

Final validation passed 112 focused tests, 552 full-suite tests and all 14 configured checks; exact commands and exit codes are in `evidence/checks/results.json`. `evidence/final-type-confirm-live-normal/` archives the final typed replay and renderer source. Its screenshot is pixel-identical to the preceding final live capture, as recorded in `evidence/type-only-confirmation-comparison/comparison.json`.

Full intermediate source trees were not archived at the time of early trials. The source revision, algorithm descriptions, raw outcomes and rejection reasons are saved, but an exact patch is not recoverable from every trace. New benchmark runs save complete renderer/harness/lockfile source archives and SHA-256 manifests. This limitation is explicit so a future LLM does not invent a missing experiment implementation.
